指针指向的内存何时释放

数组和指针的区别

我们说，一个数组 double arr[N]，即一个 double[N] 类型的变量 arr，事实上包含了 3 部分信息：

  • 数组的基地址 (&arr[0])
  • 数组的元素类型 (double)
  • 数组的元素个数 (N)

在上面这个函数中我们传入了一个 double *的指针，这么做只传递了这个数组 一部分的信息。于是我们又传了一个int的元素个数才完整表示这个数组。这就是指针与数组的一些区别。

这个函数在最开头 new 了一个类型为 double 的数组，做了一些前期的准备，然后判断需不需要计算。如果不需要计算的话，函数返回。如果需要计算的话就计算，计算后 delete 这个不再用的 temp。

但是，如果这个 if 的条件为真，它直接 return，new 出来的这个 temp 没有被释放。

也就是说，为了避免这个问题，我们应该对这个函数的每一个出口都要把他申请过的所有的资源全部释放一遍，也就是加上上面注释的内容。

总的来说这样的指针用法比较冗余，容易出错，不易维护。

考虑一些解决方法，譬如通过某种机制，默认在函数结束时释放所有指针，实际上这也是不可行的。

指针指向单个对象还是数组

实际上编译器无法判断出这个指针指的是单个对象还是一个数组，这意味着它不知道该用** delete 还是 delete0[] **,同时如果是单个对象，那么 ++p, --p也不被允许（当然数组在越界是也不行）

指针是否允许为空

C++中指针类型本身无法表达是否为空，我们需要经常自己判断指针是否为 nullptr。如果可以保证某种指针可以永远不为空的话，就可以省去空指针检查，从而提高代码效率。

小结

总的来说，如果有一个智能指针就好了,我们希望它：

  • 自动回收资源：在生命周期结束后，智能指针能够自动释放资源
  • 知道指向的是单个对象还是数组：智能指针能够根据指针的类型，自动选择 delete 还是 delete[]
  • 增加一些限制：有的时候，可以强制要求智能指针不为空

垃圾回收 |GC(garbage collection)

垃圾回收（Garbage Collection）的核心是 回收「不可达」 的对象。
Java/C#会采用一种在运行是GC的方法，但是C++并没有这么做。

如何判断对象的可达性

当一个对象不能通过任何途径被访问到时，我们称这个对象是「不可达」的。这个时候就可以回收了，总的来说有这么写判断方法：

  • Reference Counting（引用计数）
    引用计数的核心思想是为每个对象维护一个 引用计数器，记录有多少个指针指向该对象。当引用计数为零时，说明没有任何指针指向该对象，因此可以安全地回收该对象的内存。
    引用计数的优点是实现简单，且可以立即回收不再使用的对象。但它的缺点是：
    • 循环引用问题：如果两个对象互相引用，它们的引用计数永远不会为零，导致内存泄漏。
    • 性能开销：每次指针的赋值或析构都需要更新引用计数，可能会带来额外的性能开销。
  • Mark & Sweep
    这是一种更复杂的垃圾回收方式。它的核心思想是从程序的 Root Set（如全局变量、栈上的变量等）开始，递归地标记所有可以访问到的对象。标记完成后，垃圾回收器会清除所有未被标记的对象，回收它们的内存。
    它的优点是能够处理循环引用问题，但它的缺点是：
    • 暂停时间较长：标记和清除的过程可能会暂停程序的执行，影响程序的响应速度。
    • 内存碎片问题：清除过程中可能会产生内存碎片，导致内存利用率下降。

对 不可达 的对象，回收多大空间？

这个问题是一个 类型安全 的问题，而遗憾的是C++并不是一门类型安全的语言：

  • void *: C 和 C++ 都允许指针到 void * 类型的转换，这在损失元素个数的基础上进一步损失了元素类型的信息(丢失类型与大小)，导致更不知道该释放多少空间。
  • union: union 也是一个类型不安全的工具，它可以让一个变量在不同的时间点代表不同的类型，这也会导致不知道该释放多少空间。

  • 碎片
  • 停顿时间
  • Locality（地址？）

std::unique_ptr

conception

第一种智能指针叫做 unique_ptr，它定义在 <memory>头文件中。
unique_ptr是 独占所有权 的指针：

  • 一个对象只能被一个 unique_ptr拥有
  • 不能拷贝、只能移动（移动赋值那种）
  • 析构时自动释放所拥有的对象

使用方法

看看怎么用的：

unique_ptr提供了一些和普通指针差不多的功能：

  • 成员访问运算符 ->：用于访问指针所指向对象的成员。
  • 间接访问运算符 *：用于解引用指针，获取指针所指向的对象。

在函数结束时 ，owner的声明==生命周期结束了，unique_ptr会自动释放它所拥有的对象。

我们看看把 unique_ptr放到类里面的情况：
注意如果你的类成员变量时像uniqie_ptr这样能够自己管理自己的对象，那么SMF(特殊成员函数)像是拷贝赋值、构造，析构函数这些就不用写了，这也是 C++ Rule of Zero 原则的一个体现：

  • MyClass 的析构会自动触发 owner 的析构函数
  • MyClass 的移动构造和移动赋值会自动触发 owner 的移动构造和移动赋值
  • 由于 owner 的的拷贝构造和拷贝赋值是被 delete 的，所以 MyClass 的拷贝构造和拷贝赋值是被 delete 的，所以 MyClass 不能被拷贝（总之因为有智能指针所以这个类只能被转移不能被拷贝了）
    • （回顾上一节的内容：拷贝构造隐式声明被定义为删除(= delete)，如果该类有无法拷贝构造或析构的非静态成员或基类，或者该类有用户定义的移动构造（你自己写一个上一节里的右值引用什么的）或移动赋值。拷贝复制类似。）（unique_ptr就没有拷贝构造）

重载运算符

我们之前没有见过 -> 运算符重载。事实上 owner->calculate() 的语义是 (owner.operator->())->calculate()(编译器会调用owener.operator->())。而 (owner.operator->()) 返回的是 ptr，得到 ptr->calculate()。

其他成员函数

  • release()释放所有权，返回裸指针（不释放内存）
  • reset(p)释放当前对象，接管新对象 p
  • get()返回裸指针（不释放所有权）
  • operator bool()判断是否为空，可用于 if (ptr),这使得智能指针和普通指针一样可以直接用在条件语句中，即隐式转换为 bool 类型。

这边其实需要一些理解。比如说.get()返回裸指针，但是不释放所有权，这是什么意思呢？我们知道p是一个智能指针，但是如果有个函数只接受原始的那种int *的指针，或者是某些调试情况你就是要看一眼这个对象内部的状态（但是没办法做操作，因为所有权没有转移），这个时候要用.get()。

数组版本：unique_ptr<T[]>

unique_ptr对于数组版本特别又定制了一些方法：

  • unique_ptr<T[]> 提供了对数组类型的支持，自动调用 delete[] 来释放内存。
  • unique_ptr<T[]> 提供了下标运算符 operator[]，可以像使用普通数组一样访问元素。
  • 可以使用 make_unique<T[]>(size) 来创建一个动态数组，其中 size 是数组的大小。与普通的 unique_ptr<T> 不同，make_unique<T[]> 只接受一个参数，即数组的大小，而不接受构造函数参数。这是因为数组类型的 unique_ptr 不支持构造函数参数。

用法小结：什么情况需要转移所有权,什么情况不需要？

将 unique_ptr 作为引用传递给函数的情况，通常是函数需要重新设置指针的情况。这种情况下，调用者需要明确地知道函数会改变指针的指向。

  • 工厂函数（Factory Function）—— 最常见的“返回值转移”
  • 容器操作（Container Operations）—— 把对象“放”进容器或“取”出来
  • 资源管理类的移动语义（Move Semantics）
  • 自定义删除器（Custom Deleters）与资源释放

栈内存与堆内存

智能指针，所有权等等本质还是这个堆内存、栈内存的问题。所有权的转移是为了更好的销毁，那为什么要销毁呢？为了不占太多堆内存。栈变量不是挺好，离开作用域自动销毁。但是栈的大小比堆小多了，放不下这样。

std::shared_ptr

concept

shared_ptr 其实是一个更高级的智能指针版本。它高级的地方就在于它的 所有权是可以共享 的。这就是我们之前说的「引用计数」的完整版本。(前面讲过引用计数了)

当 shared_ptr 被复制时，新的 shared_ptr 会指向同一个 Control Block，并且引用计数会加 1。也就是说，shared_ptr 的拷贝是浅拷贝。

因此我们可以看到，shared_ptr 是 有额外的内存和性能开销的，并不像 unique_ptr 那样只是一个指针的包装。

几点注意：

  • 拷贝构造：引用计数加 1。shared_ptr有拷贝赋值、拷贝构造
  • 移动构造：不会增加引用计数，因为原 shared_ptr 不再指向该对象。
  • shared_ptr 可以接受 unique_ptr 的右值引用，从而将独占所有权转换为共享所有权。
  • 在赋值操作中，shared_ptr 会先减少原对象的引用计数，然后再指向新对象。如果原对象的引用计数减到 0，则会释放原对象。

shared_ptr的常见陷阱

依旧是double free 问题：

多线程下的问题：the reentrancy pitfall

在函数执行期间，如果全局 shared_ptr 被重新赋值，可能导致原对象被销毁，而函数内部仍在使用该对象的引用。

“重入（reentrancy）”在这里指：在执行一个函数的过程中，又调用了另一个可能修改全局状态的函数，并且这个修改影响到了当前函数的上下文。

回顾：Rule of Zero

老生常谈了，之前Rule of Three也是一样的，作一个更新：

  • std::string 代为管理字符串
  • STL 容器代为管理数据类型，如 std::vector 或者 std::array 代为管理数组
  • 智能指针代为管理动态内存
  • std::fstream 等代为管理文件读写

暂未讨论的话题

  • 线程安全: 在多线程环境下，尤其是 shared_ptr，需要保证线程安全。这个话题值得深入讨论，但由于我们没有涉及多线程的内容，暂时不展开讲解。
  • 异常安全: 虽然我们还没有设计异常处理，但智能指针除了之前提到的各种优点外，还能提供较好的异常安全性。
  • std::weak_ptr: C++ 标准库中有几种智能指针，除了 shared_ptr 和 unique_ptr 之外，还有一个 weak_ptr。weak_ptr 是与 shared_ptr 共同使用的，它是 shared_ptr 的一个弱引用。所谓弱引用，就是即使 weak_ptr 存在，如果最后一个 shared_ptr 被销毁，对象仍然可以正常析构。weak_ptr 不影响对象的析构。weak_ptr 的一个常见用途是在实现 cache 时使用，大家有兴趣的话可以自行查阅相关资料。
  • 自定义删除器: shared_ptr 和 unique_ptr 都支持自定义删除器。默认情况下，对于非数组类型，删除器是 delete，对于数组类型，删除器是 delete[]。但在实际应用中，我们可能需要管理非普通指针，比如 FILE*，这时我们希望在析构时调用 fclose 而不是 delete。这种情况下，我们可以自定义删除器。
  • 继承关系中的智能指针: 在 C++ 中，子类的指针可以转换为基类的指针。同样，子类的智能指针也可以转换为基类的智能指针。这是对普通指针行为的一种模仿。如果大家有需要，可以进一步了解这方面的内容。
