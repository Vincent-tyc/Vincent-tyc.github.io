lvalue & rvalue

Introduction

对于 int n，为什么n = 1;是合法的，而1 = n;这是非法的？首先这不是类型的原因，两者的类型都是一样的。

实际上，对于 1 = n;的语句，编译器的报错是： Expression 1 is not assignable。也就是说n是一个 表达式，指向一个对象，占用一块内存，其内存表示了一个值。而 1 不指向一个对象，它不占据内存，这个值与对象没什么关联。

表达式和语句

**表达式（expressions）**是运算符和操作数的序列，用来指明一个运算。

操作数也是表达式，因此任何操作符的操作数要么是 primary expressions（基本表达式），要么是其他表达式。顾名思义，primary expressions 是最基本的表达式。它们包括：

  • this
  • 字面量，例如 2 或者 "Hello, world!"
  • id-expressions，例如 n 或者 std::cout
  • lambda 表达式，例如 [](int & n) { n *= 2; }
  • fold-expressions(折叠表达式？)
  • requires-expressions（需要表达式？）

总之，表达式可以产生值，同时可能导致副作用：

  • 2 + 2 这个表达式产生 4 这个值，没有副作用；
  • x = y = 2 这个表达式产生的值是 2，产生的副作用是把 x 和 y 赋值为 2；
  • 如果有 void print(int x){ std::cout << x; }，那么函数调用表达式 print(1) 没有产生值，但是有把 1 打印到标准输出的副作用。

语句（statements） 是按顺序执行的C++程序片段，任何函数的函数体都是语句的一个序列。C++包含以下这些语句：

  • labeled statements EXIT: return 0;
  • expression statements n = 1;
  • compound statements { n = i; i++; }
  • selection statements if (n == 1) break;
  • iteration statements while (n--);
  • jump statements break;, return 0;, goto EXIT;
  • declaration statements int n = 0;
  • try blocks
  • atomic and synchronized blocks (TM TS)

回过来，虽然n 和 1都是表达式，但是它们的性质是不一样的。这样设计的原因是让一些表达式的值 不必占据内存，有助于我们实现优化。1不是对象，这样代码中的内存操作会减少，这是一件好事情。

我们继续研究表达式的性质，除了我们熟悉的 **类型（type）**之外，还有一个是 value category,也就是值类别。

我们把表征一个对象的表达式称为 左值（lvalue），它可以出现在赋值表达式的右边；而把一个值不与对象关联的表达式称为 右值（rvalue）,只能出现在赋值表达式的右边。

比方说，对于 int m;, m + 1 = 2; 这个表达式也是非法的，因为 m + 1 这个表达式的值并不表征一个实际的对象。对于 int foo();, foo() = 2; 也是非法的，因为 foo() 这个函数调用表达式的值也不表征一个实际的对象。

关于内存占用

右值不一定占用内存，也就是说字面量变得足够大的时候，汇编一条语句装不下，此时右值会占据一定内存。

同时，左值表征的对象虽然 从概念上说 一定占据内存，但是编译器实际会作出一些优化使它不占用内存。比如 只放在寄存器中 或者在 编译时完成相关的计算从而删除它 。譬如定义 const int n = 2; 有可能会使得所有对 n 的使用被替换成 2，从而左值 n 表征的对象在生成的程序中不再存在（因而不再占据内存），但是如果我们使用了 std::cout << &n;，那么 n 就一定会存在并占据内存以满足这一输出的要求。（要使用n的地址的时候，显然一定会占点内存的）（后面的讨论始终是认为 lvalue是会占据内存的）

lvalue

lvalue 用来表征一个 对象，或者说一个内存位置。因此 lvalue可以被取地址，以及初始化引用。

不过有些左值不能出现在赋值表达式的左边，比如 const的字符数组什么的，显然里面的const char类型字符无法被修改，这样的左值被称为 non-modifiable lvalues。

左值包括：

  • 任何有名字的表达式 都是左值，唯一的例外是枚举4；
  • 内置 的 ++a, a = b, a += b, *p, p->m 是 lvalue
  • 如果 a[n] 的操作数之一是 array lvalue 或者 pointer，则是 lvalue
  • 如果 a 是 lvalue，m 是成员变量，则 a.m 是 lvalue；如果 m 是成员变量，p->m 是 lvalue
  • 返回值为引用类型的函数调用表达式是 lvalue，因为返回值表征的是一个对象
  • 目标为引用的 cast expression(强制类型转换表达式) 是 lvalue，如 (int&)(x)，这一操作可以理解为初始化一个引用
  • 除了字符串字面量是 lvalue（因为字符串字面量的类型是 const char[N]）以外，其他字面量都是 rvalue。（用户自定义字面量不一定，我们会在后面讨论这个话题。）

lvalue-to-rvalue conversion

左值表征一个对象，而右值则是一个值。当我们将一个左值放在赋值表达式的右边时，如 n = m;，则会发生 lvalue-to-rvalue conversion，因为此时我们关注的是 m 这个对象中的值，而不是 m 这个对象本身。

rvalue

如果一个表达式不是左值，也就是不表征一个对象，那么它就是 右值。

右值表达式用来：

  • 计算内置运算符的一个操作数
    • 例如 1 + 2 + 3 中（假设从左到右计算），1 和 2 是 rvalue，作为第一个 + 的操作数；1 + 2 也是 rvalue，作为第二个 + 的操作数
  • 初始化一个对象
    • 初始化出的对象称为这个表达式的 result object
    • 例如 int i = 1 + 2;，或者 void f(int x);, f(1)。

右值包括：

  • 枚举数 (enumerator)（枚举数实际上是一个整数常量） 和除了字符串字面量(字符串是数组构建的，有内存)以外的字面量是 rvalue
  • 内置的 a++, a + b, a || b, a < b, &a 等表达式是 rvalue
  • 返回值不是引用类型的函数调用表达式是 rvalue
  • 目标为非引用类型的 cast expression 是 rvalue，如 int(3.0)（和地址没关系的？）
  • this 是 rvalue
  • lambda 表达式是 rvalue

小结

lvalue 是 locator（用于确定对象位置或引用的机制），它计算出一个对象。（的位置）

而 rvalue 计算出的结果用于初始化对象 (result object)，或者执行进一步的计算。

把右值绑定给 const引用

首先，int * pi = &3;这种把引用（指针）指向一个rvalue是非法的。不过将一个临时对象绑定给一个const引用时合法的。比如const int& cr = 1;可行，但是 1 是右值，不占内存。但绑定到 const 引用时，编译器必须创建一个临时对象来存放这个值，然后让引用绑定到这个临时对象上。所以这里也产生了一个临时、但占内存的东西。

prvalue

prvalue要完成的事情：

  • 计算内置运算符的一个操作数
  • 初始化一个对象
    • int i = 1;
    • Foo func();, Foo f = func();
      • 此时会发生 copy elision(拷贝消除)
    • const int & r = 1;
      • 此时，prvalue 转为 xvalue

xvalue————Temporary materialization(临时显现？)

任一完整类型 T 的 prvalue 都可以转换为 T 的 xvalue，这一转换称为 temporary materialization。这一转化用 prvalue 初始化一个临时对象，产生表示这个临时对象的 xvalue。

temporary materialization 发生在如下情形中：

  • 将引用绑定到 prvalue，如 const int & r = 1;
  • 对类 prvalue 进行成员访问，如 foo().x;（此时 x 也是 xvalue）
  • 对于一个数组 prvalue a，对其进行 subscript a[1](访问下标) 或者 array-to-pointer convsersion(数组到指针的转换) f(a) 时
  • 当 prvalue 是一个 discarded-value（值丢弃） expression（为了其副作用而使用，其值本身没有被使用）时（如a = 1; a++; cout << endl;）

Note

有 struct Foo {}; struct Bar : Foo {};，那么 Foo f = Bar(); 发生了什么？

  • 首先，Bar() 是一个 cast，得到一个 Bar 类型的 prvalue；
  • 我们要用这个 prvalue 构造 f，这时会用到 Foo 类隐式生成的移动构造函数 Foo::Foo(Foo &&);
  • 为了将这个 prvalue 传递给 Foo &&，会发生一次 materialization
  • 即，实际发生的是 Foo f = Foo(static_cast<Foo &&>(Bar()));（变成xvalue,即创建一个临时对象来承载这个prvalue）
