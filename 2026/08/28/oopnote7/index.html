STL初步

STL,全称Standard Template Library,也就是标准模板库。简单来说这个库里面大量利用了模板提供的泛型思想，从而实现了很多常用的数据结构与算法。这些数据结构通过类模板实现，而算法是通过函数模板实现的。

为什么要使用STL?

STL提供了 容器库（Containers library） 和 算法库（Algorithm library），这些库里面包含了大量常见的数据结构，这样你刷力扣或者写程序的时候不用像C语言那样自己手搓而是直接调用了。

  • auto it = std::find(v.begin(), v.end(), 3);
    • 这里的 v.begin() 和 v.end() 获取容器 v 的开始和结尾，其返回值类型是这个容器的 迭代器 (iterator)；现在我们可以把它简单地理解为「指针」。（是否就是python里的迭代器？）

**迭代（iteration）**

One cycle if a set of iinstructions to be repeated,即循环中的一次。在这个语境中我们的循环是为了遍历数据结构，迭代要做的事就是找到下一个元素，和访问元素内容。

这里的someType就是用来 迭代（iterate）这个数据结构 的变量的类型。

这里 SomeType 就是用来迭代 (iterate) 这个数据结构的变量的类型。显然，这个类型并不是数据结构中元素的类型，因为对于一个数组 int a[10];，我们需要通过一个 int * 才能找到下一个元素，而不是通过 int。即，这个循环形如 for (int * ptr = a; ptr != a + N; ++ptr) { print(*ptr); }。也就是说，这里的「开头」是 a，「末尾」是 a + N，「判断是否到达末尾」的方式是 ptr != end()，「找到下一个元素」的方式是 ++ptr，「访问元素内容」的方式是 *ptr。

也就是说，我们通过指针能够完成「找到下一个元素」「访问元素内容」以及「比较」的功能，也就是迭代时所需的功能。因此我们将指针称为数组的 迭代器 (iterator)。迭代器并不是一个具体的数据类型，而是一类东西的统称。

简单说，如果是一个int数组，那么迭代器就是 int* 指针，如果是一个vector<>int的容器，那么迭代器就是vector<int>::iterator。

显然，对于其他数据结构，我们没有指针这样简单的方式来实现遍历。不过我们可以通过运算符重载的方式来为其他数据结构提供它们的“指针”：

运算符重载之后，for (MyIterator it = c.begin(); it != c.end(); ++it) { print(*it); }这样的写法又可以了。

Q&A:

1.每个类前面加一个template<typename T>的目的是什么？
为了使这个类成为一个通用的 “模具”， 使MyLList<int> 或 MyLList<string>不同类型的输入都可以实现。
2.begin() 和 end() 是标准库自带的吗？为什么要定义它们？
这个是自己写的成员函数，使得范围 for 循环（for (auto i : list)）和标准库算法（ std::find、std::for_each）得以实现。
3.Node(const T &data = T()) : data(data) {} 是什么？
这是 Node 结构体的构造函数，它允许你用一个值来创建节点。

  • const T &data：待存储的数据，传引用避免拷贝。
  • = T()：给参数一个默认值，用 T 类型的默认值（比如 int 的 0）来构造节点。这样你可以写 Node<int>() 来创建一个值为 0 的节点。
  • : data(data)：用传入的 data 来初始化当前节点的成员变量 data。

4.Node<T> 是什么？
Node<T> 是 Node 这个类模板的实例化。

  • Node 是模板的名字。
  • <T> 是模板参数，表示“用类型 T 来生成具体的 Node 类”。
  • 在这个例子中，MyLList<int> 里的 Node<int> 表示这是一个存储 int 类型数据的节点。

5.using iterator = MyIterator; 这里的 iterator 是标准库的 iterator 吗？

不是。这句代码的意思是：MyLList 里有一个类型叫 iterator，它实际上就是 MyIterator。这样，外部代码可以写 MyLList<int>::iterator，看起来和标准库容器（如 vector<int>::iterator）的用法一致，但本质上它指向你自定义的迭代器。

6.using iterator = MyIterator;是何意味？

在类内部使用的时候，随便你把迭代器叫什么。但是这里取别名，是因为，在外部调用时（如int main()中），C++ 标准库中有一些“基础设施”会默认你的容器内部有一个叫做 iterator 的类型。如果你的容器里没有这个叫 iterator 的类型，那些基础设施就无法为你工作。
所以只要设定好Container::iterator 这个统一的别名即可。

从这个例子中，我们可以理解 迭代器 (Iterator) 解决的问题。我们知道，我们写程序的目的就是 处理、查询、使用数据，数据结构和算法是我们的工具。在概念层面上，各种容器或者数据结构的意义是以一定的方式或者性质 容纳 数据，但是它本身不具备处理数据的能力；而各种算法的意义是按一定的方法 处理 数据，它本身并不持有任何数据。而迭代器就是它们之间的桥梁——一个容器可能是一个数组、一棵二叉树、一个链表，或者其他任何可能的数据结构；一种算法需要对容器做遍历或者其他类型的访问；但是遍历一个数组和一棵二叉树的方式肯定是不同的——迭代器存在的意义就是 通过运算符重载或者其他方式，来向算法隐藏容器的不同细节；算法只需要使用 ++ 就能获得下一个元素的迭代器，通过 * 就能访问当前迭代器指向的元素，它不需要关心到底是如何访问的；这其实上就是指针的抽象。通过这种方法，STL 保持了它的简洁性，提升了代码的复用。

迭代器大抵是一种数据结构与算法之间的Bridge。

所以，for (auto &a : c)是如何实现的也很简单。对于for (auto it = c.begin(); it != c.end(); ++it) {auto &a = *it; /* A */}，它的成员函数 begin() 和 end() 返回的都是某种迭代器；而这些迭代器都重载了 ++ 等运算符…………然后就这样适配了不同的数据类型。

迭代器的分类

我们在前一节中得知，std::vector 和 std::unordered_set 之类的容器都是有迭代器的，我们可以通过迭代器遍历它们。我们还知道，我们可以通过 std::sort 来对 vector 中的元素进行排序。请问：我们是否可以用 sort 来对 unordered_set 中的元素进行排序？如果不能，为什么？

Unordered Associative Containers(无序关联容器) 的实现

先插一嘴，什么是无序关联容器？set multiset map multimap这些键、键值对。

我们知道，Unordered Associative Containers 基于哈希表来实现，各个元素会根据给定的哈希函数计算出一个哈希值。每个哈希值对应一个链表，元素根据哈希值放到对应的链表 (“bucket”) 中。当进行遍历时，实际上会遍历所有有元素的哈希值，并遍历其链表中的每一个元素。

不过，我们考虑这样一个问题：如果有 $m = 10^6$ 个 bucket，但是只有 $n = 100$ 个元素，如果直接遍历 bucket 的话复杂度是 $O(m + n) \gg O(n)$ 的。

因此，实现中会额外用一个单向链表维护所有有元素的 bucket 列表，遍历时根据这个列表去找元素，复杂度就仅是 $O(n)$ 的了。

好了这下我们可以理解为什么这样的数据结构不能进行排序了。但如果一定要写一个排序呢？

原因：sort 的实现类似快速排序1；而快速排序本身是需要 随机访问 容器中的元素的，即能够以 $O(1)$ 的时间使用类似 c[i] 的方式访问到容器中的任意一个元素；同时也需要能够以 $O(1)$ 的时间计算两个元素之间的 距离。但是，unordered_set 本身显然不能够满足上述要求。

先说结论，迭代器的能力有强有弱，具体分为以下这些：

  • Input Iterator : 能够用来标识、 遍历 一个容器中的元素，能够从所指的元素中 读取 值。
    • Input Iterator 只需要保证 单趟 算法的有效性：一旦一个 Input Iterator it 被 ++ 后，它之前所指的值及其所有拷贝都不再需要保证有效性。适用于istream的输入流，只能读一次，不能回头。
  • Forward Iterator : 在 Input Iterator 的基础上，能够支持 多趟 算法。单向链表，只能向前移动，适用于 forward_list。
  • Bidirectional Iterator : 在 Forward Iterator 的基础上，能够 双向移动。即双向链表，但不能随机跳转，适用于list。
  • RandomAccess Iterator : 在 Bidirectional Iterator 的基础上，能够在 常数 时间内移动从而指向 任一 元素。适用于 deque。
  • Contiguous Iterator (C++17) : 在 RandomAccess Iterator 的基础上，逻辑上相邻的元素在内存里 物理上也相邻。（连续内存）
    • 指向数组中元素的 指针 满足 Contiguous Iterator 的所有要求。使用于 vector 和 array。
    • 支持 随机跳转、双向移动、计算距离
  • Output Iterator : 它和 Input Iterator 类似，需要能够用来标识、 遍历 一个容器中的元素，能够向所指的元素中 写入 值；同样不需要保证多趟算法的有效性。 适用于ostream的 输出流，只能写一次，不能回头，不能读取。
    由于 Output Iterator 和前述 5 个类型是相互独立的。因此，我们称满足前述 5 个中某一个、同时还满足 Output Iterator 的迭代器为 mutable 的。

为什么集合系列容器没有 mutable 迭代器？

指 set, unordered_set, multiset, unordered_multiset，因为集合按元素的值做了排序 / 哈希；如果允许通过迭代器修改，那么有可能导致顺序被破坏。

为什么 map 系列容器有 mutable 迭代器？

map 系列容器可以看做键值对的集合，其元素的类型是 std::pair<const Key, Val>；可以看到它的 first 元素类型是 const Key，因此虽然迭代器是 mutable 的，但是只能用来修改 value，而不能用来修改 key。

算法通过操作来隐式地要求迭代器类别

算法并不主动检查你的迭代器是什么类型，而是 直接使用迭代器支持的操作。如果你的迭代器不支持，编译器就会报错。
比如 sort 需要传入的迭代器满足 Random Access Iterator；这一限制的实现方式其实就是， sort 的实现中会包含 it1 - it2 ， it + n 之类的运算，如果不支持这些运算就无法通过编译。
同时，对于 set、map、multiset、multimap 这类有序关联容器，所有与“顺序查找”相关的操作（lower_bound、upper_bound、find），都优先使用容器自带的成员函数，而不是标准库的通用算法。(它们的底层实现是 红黑树，而红黑树自带 $O(log n )$ 的 二分查找，采用 Bidirectional Iterator 双向链表 的查找复杂度退化成 $O(n)$ 了)

Duck Typing(鸭子类型)

If it walks like a duck and it quacks like a duck, then it must be a duck.

在C++模板中，这意味着：如果它能做++ 、* 、!=，那么 它就是迭代器。

sort 能对数组和 vector 排序，是因为指针和 vector 的迭代器都支持它需要的 +、-、* 等操作；它不对 list 工作，是因为 list 的迭代器不支持这些操作。(迭代器是写在容器类内部的，而sort是一个算法，写成一个独立的模板函数)

补充

这其实就再次向我们展现了 template 所支持的泛型编程的意义——面向对象编程允许我们写一个「支持某一类型（基类）以及属于这一类型的其他类型（子类）」的函数；而泛型编程则允许我们写一个「支持满足某一条件（拥有某些特定成员）的所有类型」的函数。

也就是说，在面向对象编程中，我们通过继承和多态来将不同的类型抽象起来，用「子类对象是一个父类对象」的逻辑来在需要时把子类对象当做父类对象使用，从而提高代码的简洁性和重用度；而在泛型编程中，我们通过类似上文中 sort 的方式，将不同类型共同具有的一些函数或字段作为要求。即，面向对象的函数所提出的要求是 “is”，即通过「子类对象 is a 父类对象」的方式做抽象，而泛型编程的函数所提出的要求是 “has”，即通过「某个类型 has 某些成员」的方式来做抽象。这也是泛型编程相比面向对象编程来说更加自然以及自由之处。

sort的第三个参数

这里我们考虑的一个具体的问题是：在template <-1-> std::sort(-2-)这样的sort模板函数里，自定义比较函数是怎么实现的？如何适配有和没有自定义比较函数的两种情况的？

简单来说，sort 通过 “模板 + 运算符重载” 实现了这种灵活性，遵循的还是那个核心思想：只要你的类型能像函数一样被调用（支持 () 操作），它就能充当比较器。

提醒：sort内部有一个comp(a,b)，每次需要比较两个元素谁大谁小时，sort 就会调用它。但是comp(a,b)会随你第三个参数传入（或者空着）而变化：

于是我们来考察sort的第三个参数可以放什么（前两个参数一般是first和end的迭代器，对吧）

在 C++ 中，如果 a 是一个对象，那么 a(b...) 其实等同于 (a).operator()(b...) ，其实就是将 b... 作为参数列表，调用了 () 运算符。我们把 () 运算符称为 函数调用运算符 (function call operator)，顾名思义，这个运算符表示函数调用。也就是说，如果我们有一个 greater<T> 类的对象 cmp ，那么我们就可以通过 cmp(a, b) 来调用 (cmp).operator()(a, b) ，从而返回比较的结果。
再回到 sort(v.begin(), v.end(), greater<int>()); 中来。我们可以看出， greater<int>() 其实就是调用 greater<int> 的默认构造函数，构造了一个 greater<int> 类型的对象传递给 sort 。不妨设对应形参名为 cmp ，那么在 sort 中，我们就仍然可以通过 cmp(a, b) 来调用 greater<int> 中的 operator () 来实现比较。

没看懂啥意思 要注意理解()的用法

总之，sort 的第三个参数不一定要是函数，它可以是任何“可调用”的东西——函数指针、函数对象、lambda 表达式。只要它能被 () 调用，sort 就能用它来比较元素。这就是 C++ 泛型编程中“不关心具体类型，只关心行为”的体现。

函数对象

函数对象就是“能像函数一样被调用（即可以使用()运算符）的对象”。

更具体的说：

  • 函数指针————bool(*cmp)(int,int)
  • 重载了operator()的类的对象————greater<int> cmp; cmp(3, 5)
  • lambda表达式————[](int x){return x > 0;}

等等，什么是 对象(object)？

对象要有值、类型、size、声明周期等属性，它描述的是一块内存上的数据及含义。按照这个定义下面这些实体不是对象：

  • struct / class，包含其模板及特化，它用来 描述 一类对象的内存安排（虽然它们可能包含虚函数表）；
  • struct / class 的非 static 成员变量；
  • function，包含其模板及特化，它是一段代码；
  • reference，它只是已有对象或函数的别名，编译器不必为它们分配内存（因此不存在引用数组、引用的引用和指向引用的指针）；等。

泛型编程与OOP

自 1987 年左右，C++ 及其编程风格开发的重点转向了模板、static polymorphism(静态多态)、泛型编程和多范式编程。

泛型编程是基于「参数化 (parameterization)」的一种编程范式，我们可以将一个类型或者一个算法参数化，从而将一种数据结构或者算法一般化。

泛型编程相对 OOP 更加灵活，它并不依赖继承的结构。OOP 有时被描述为 “ad hoc polymorphism（特设多态）”，而泛型被称为 “parametric polymorphism（参数多态）”，泛型相较于 OOP 更加结构化（更加抽象）。

对于 C++ 而言，泛型编程的解析均发生在编译时（因此也被称为 static / compile-time polymorphism），并不需要运行时的 dispatch（根据参数类型进行不同选择？）；因此对于那些对运行时性能要求较高的程序，泛型编程往往更受欢迎。

泛型编程也不是万能的，在一些继承结构明显的情况下使用 OOP 比泛型更加方便和自然。而且除了类似写库之类有参数化需求的情况以外，泛型编程可能也并不完全需要。

同时在 C++ 中，模板带来方便的同时，也带来了一些不尽人意的后果——错误检查滞后、出错信息非常糟糕。为了解决这个问题，C++20 引入了 concepts 以及配套的「新版 STL」—— ranges。我们将在后面的章节讨论它。
